## 📌 2026-09-03 11:25 ｜ 移动端弹窗选项卡（TAB）权重覆写与三等分防截断适配

### 1. 问题背景与根因排查
- **问题现象**：在解决弹窗视口垂直居中溢出后，手机端弹窗整体居中与圆角恢复正常，但横向选项卡（TAB）右侧出现内容截断，第三个标签“懒人攻略”的“略”字被右边缘裁切了一半。
- **技术根因**：
  1. **CSS 选择器权重压制（Specificity Conflict）**：在 `style.css` 第 3609 和 3613 行，桌面端使用了高权重复合选择器 `.detail-modal .modal-tabs`（权重 `0,2,0`）与 `.detail-modal .modal-tab-btn`（权重 `0,2,0`），强行注入了 `padding: 0 30px;`、`padding: 17px 24px;` 及 `font-size: 16px;`。
  2. **移动端单类规则失效**：移动端媒体查询仅声明了单类 `.modal-tabs` 与 `.modal-tab-btn`（权重 `0,1,0`），导致移动端紧凑样式完全被桌面端压制。
  3. **横向容器物理溢出裁切**：手机屏宽下卡片可用宽度仅 300px 左右，而桌面端样式强制需要 396px 以上空间，结合 `overflow-x: hidden;`，直接导致右侧 30~50px 内容被硬生生切掉。

### 2. 治理方案与落地实施
1. **高权重覆写移动端 TAB 容器 (style.css)**：
   - 使用 `.detail-modal .modal-tabs` 将容器内边距由 30px 紧凑收敛至 6px：`padding: 0 6px;`。
   - 启用横向弹性自适应与隐藏原生滚动条：`display: flex; justify-content: space-around; overflow-x: auto; overflow-y: hidden;`。
2. **三等分自适应按钮排版 (style.css)**：
   - 使用 `.detail-modal .modal-tab-btn` 设置 `flex: 1 1 0; text-align: center; padding: 12px 4px; font-size: 14px;`，让三个 TAB 在任意手机屏幕宽度下均分卡片宽度。
   - 修正激活状态下划指示条 `.detail-modal .modal-tab-btn.active::after` 的定位为 `left: 12px; right: 12px;`，确保下划线始终平稳居中。
3. **备份与验证**：
   - 备份 `style.css` 至 `style.css.bak_20260903_mobile_tabs_fit`。
   - 执行 `npm run build` 并通过 `verify-build.js` 验证全量产物。

## 📌 2026-09-03 10:55 ｜ 移动端大图关闭点击穿透防二次自动打开修复

### 1. 问题背景与根因排查
- **问题现象**：在解决大图关闭闪退回列表问题后，手机端出现新连带现象：在大图界面点击右上角 X 关闭时，画面瞬间回到景点详情弹窗，紧接着又自动把大图重新打开。
- **穿透二段触发根因**：
  1. **底层封面大图热区覆盖**：详情弹窗顶部封面大图 #modal-img 占满弹窗顶部区域（高 160px ~ 220px，宽 100%），全屏大图关闭按钮 image-viewer-close 的正下方正处于封面大图的触控区域内。
  2. **手势抬起派发 click 命中封面图**：用户在 pointerdown 触发大图关闭瞬间画面切回详情弹窗，用户手指随后离开屏幕，浏览器在原坐标派发 click 点击事件，穿透命中了正下方的封面大图 #modal-img。
  3. **封面图监听未设防重开大图**：封面大图绑定的点击事件未检查大图关闭冷却状态，因大图刚才已被隐去，isImmersiveImageViewerOpen() 判定为 alse，遂将本次穿透点击误判为用户要再次查看大图，立刻调用 openImmersiveImageViewer() 重新打开大图。

### 2. 治理方案与双重防御
1. **全局捕获阶段阻断穿透点击（Global Capture-Phase Interceptor）**：
   - 在 window 级别注册捕获阶段（Capture Phase，capture: true）的 click 拦截器。
   - 当检测到距离大图关闭不足 600ms（Date.now() - imageViewerClosedAt < 600）时，在事件流最顶层直接执行 preventDefault()、stopPropagation() 与 stopImmediatePropagation()，确保穿透点击根本无法传递至页面任何 DOM 节点（无论封面图、详情关闭按钮还是背景遮罩）。
2. **大图打开入口冷却防御锁**：
   - 在 openImmersiveImageViewer() 函数入口与 modalImage / modalImageExpand 点击监听处，增加 if (Date.now() - imageViewerClosedAt < 600) return; 冷却保护，彻底切断连环误触重开链路。

## 📌 2026-09-03 10:45 ｜ 移动端沉浸式大图关闭防穿透与详情弹窗闪退修复

### 1. 问题背景与根因排查
- **问题现象**：在手机端点击进入景点详情弹窗后，点击顶部图片进入全屏大图模式；在大图模式下点击右上角关闭按钮（X）时，界面直接关闭并闪退回省份景点列表，未能停留在景点详情弹窗。
- **历史变更审计**：查阅 `docs/CODEX_IMAGE_GALLERY.md` 记录发现，2026-09-03 10:04 曾进行“手机大图关闭性能修复”，将大图 X 按钮监听改为 `pointerdown` 即时隐藏 DOM，意图消除关闭延迟。
- **穿透闪退根因**：
  1. **物理触控热区完全重叠**：大图关闭按钮 `.image-viewer-close`（右上角 `top: max(18px, ...); right: max(18px, ...)`）与底层详情弹窗的关闭按钮 `.modal-close-btn`（右上角 `top: 16px; right: 16px`）在手机屏幕上物理位置重叠。
  2. **手势未闭环与事件穿透**：触屏手势序列为 `pointerdown` → 手指抬起 → `pointerup` → `click`。当手指按下瞬间 `pointerdown` 立即隐藏 `#image-viewer`，手指尚未抬起；手指离开屏幕时，浏览器在原坐标派发的 `pointerup` 和 `click` 穿透命中正下方的 `.modal-close-btn`。
  3. **状态判定失效导致连环关闭**：`.modal-close-btn` 响应 `pointerup` 执行 `handleModalClose()`，因大图已被设为 `hidden`，`isImmersiveImageViewerOpen()` 判定为 `false`，从而误将详情弹窗当成关闭目标调用 `closeModal()`，造成全流程连环关闭并闪退到列表。

### 2. 治理方案与防御设计
1. **引入时间戳冷却防御锁（ImageViewer Close Guard）**：
   - 增加全局变量 `let imageViewerClosedAt = 0;`。
   - 无论通过 X 按钮还是遮罩关闭大图，调用 `closeImmersiveImageViewer()` 均立即标记当前时间戳 `imageViewerClosedAt = Date.now()`。
   - 底层详情弹窗所有关闭入口（`.modal-close-btn` 的 `pointerup`、`click`，背景遮罩点击 `detail-modal`，以及 ESC 快捷键）均增加 600ms 冷却拦截：若距离大图关闭不足 600ms，直接抛弃穿透事件，严禁关闭详情弹窗。
2. **手势闭环安全处理**：
   - 保持大图 X 的极速响应体验，同时在大图 X 与大图背景的关闭事件中阻止默认行为与冒泡传播。
3. **备份与验证**：
   - 备份原文件至 `app.js.bak_20260903_image_close_passthrough`。
   - 重新执行 `npm run build` 编译生产 `dist/`，更新静态数据与脚本指纹。
